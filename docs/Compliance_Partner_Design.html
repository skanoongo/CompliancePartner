Compliance Partner

How the application collects SOX control evidence from Workato and NetSuite, carries it through human validation and sign-off, and uses AI agents to draft workpapers without ever reaching a conclusion on anyone's behalf.

1Overview

Compliance Partner is a web workspace for three lines of defence. Control preparers produce monthly and quarterly evidence for IT general controls, compliance monitors watch for exceptions, and internal auditors test controls and write workpapers. Behind specific controls are real evidence runs: a runner container signs in to the system under review, photographs what it shows and builds the evidence workbook. Every other control on the page is a labelled simulation.

Design principles

  • Read-only against systemsCaptures navigate and photograph. They never start, stop, edit, create or delete anything in Workato or NetSuite.
  • Evidence shows where and whenEvery screenshot is a whole-screen capture with the browser address bar and a clock, not a page render.
  • Stop rather than guessA wrong workspace, an empty user list or an unreadable report ends the run. Evidence for the wrong population is worse than none.
  • Drafts, never conclusionsAI agents prepare drafts and open items. Reviewer and sign-off fields stay blank; people validate and sign.
  • Deny by defaultSigning in grants nothing. Systems and modules come from an administrator's assignment, checked on the server for every request.
  • Simulations say soA control backed by a real capture carries a Live capture badge. A tool that looks the same either way eventually gets believed when it should not.

2Architecture

Why a whole desktop instead of a headless browser

A page screenshot proves what some markup rendered to. Change-management evidence has to show where the page came from and when: the address bar and a clock. The container therefore has a screen. Xvfb has no window manager, so the browser is placed below the clock strip instead of over it, which makes a capture without a timestamp impossible. The same reason rules out running two captures at once: they would photograph each other's windows, so a second request gets 409 busy.

The directory of users lives on the server in /data/users.json. A role decides which modules a person may open; per-user scopes decide which SOX systems they may work on. Both are enforced by the API, not only hidden in the page.

  • Compliance Monitoring (second line): exception lists per check, the termination reconciliation dashboard, reports and CSV export.

4Identity and security

The runner holds a browser that is signed in to Workato and exposes it over /session for SSO. Without a login in front of the site, anyone who could reach it would have an interactive, authenticated Workato window. Sign-in closes that.

Sign-in

  • Okta OIDC, authorization code flow with PKCE: /auth/login → Okta → /auth/callback. The ID token is verified against Okta's JWKS (signature, issuer, audience, expiry) before the runner issues its own signed session cookie.
  • Local mode for a trusted machine without Okta: a name is taken at face value, and the landing page says so.
  • nginx calls /auth/verify on every gated request. Unsigned browsers are redirected to /login; JSON requests get a plain 401.
  • After sign-in people land on /choose, the system picker, which offers only the systems assigned to them. The Compliance Partner name in the top bar links back there.

Authorization

  • Every capture, SOC 1 job and audit draft checks users.may_use(who, system) on the server. A request built by hand cannot widen scope; it gets 403 not_entitled.
  • Agent jobs are visible only to their owner or an Admin. Another user asking for the job or its files gets 404, so a job ID reveals nothing.

Secrets

  • Doppler is the source whenever DOPPLER_TOKEN is set, and then the only source: the local YAML is not read, so a rotated credential cannot come back from disk. Secrets are fetched into the runner process, not exported into the capture's environment.
  • Per-system credentials follow ENVIRONMENTS_<SYSTEM>_<FIELD>, for example ENVIRONMENTS_WORKATO_PASSWORD. A new system needs secrets, not code.
  • Passwords leave only through the login form. environments.public() is the only view the page sees, and redact() scrubs any secret from log lines shown on the page.
  • The AI key (OPENAI_SA_KEY) is never returned by any route; config endpoints report only whether it is set and which model is used.

5.1 Control preparation lifecycle

Every control, live or simulated, moves through the same four steps. A capture replaces where the evidence comes from; it never replaces what a person then does with it.

stateDiagram-v2
  direction LR
  [*] --> Prepare
  Prepare --> HumanValidation: evidence ready
  HumanValidation --> Prepare: re-run or corrected
  HumanValidation --> ManagementReview: acknowledged, submitted
  ManagementReview --> HumanValidation: changes requested
  ManagementReview --> SignOff: approved
  SignOff --> [*]

In human validation the preparer reviews the evidence, resolves any warnings the run recorded, and acknowledges responsibility for the completeness and accuracy of the source evidence and population, and for independently validating any AI-generated content. That acknowledgment unlocks the download; it does not certify the review is complete. Management review then signs off or requests changes.

What decides the scope

  • A recipe list with one row per recipe: Tab | Folder | Folder ID | Recipe ID | Recipe Name | Group | Capture | Notes. Capture=Y rows are photographed; Capture=N rows are known and never flagged as new; rows with a name but no ID are resolved against the folder by name.
  • Source, in order: config_csv, then config_sheet in the Workato environment, then the built-in list. The built-in list follows the workspace: CW Agentic (and its Development environment, which the service account signs in to) uses the CW Agentic list of 4 tabs and 12 captured recipes; Production keeps the classic CoreWeave list.
  • A CW Agentic run labels its month, so the folder and workbook are named Workato CM Review - October 2026 - CW Agentic.xlsx and never mix with a Production run.
Why the workspace check stops the runFolder IDs are per workspace. Evidence from the wrong workspace looks completely normal and describes the wrong set of recipes. The check waits up to 10 minutes, logging what it sees, and then exits instead of capturing.

5.3 User access review, UA-04

The Workato capture opens the workspace's collaborator listing, confirms each candidate page really lists people, follows pagination to the end, and reads each person's name, email, role and status exactly as displayed. People are sorted into active, inactive or suspended, and pending invitation.

  • An unfamiliar status is marked unrecognised with a warning, never read as "no access". Under-counting who has access is the one mistake a review must not make.
  • If no page qualifies as a real list of people, the run fails and names every page it tried. "No users found" and "could not find the user list" are different statements.
  • Optional cross-check against the Workday "SOX Audit - Terminations" export (uar_terminations), and extra access pages such as Workato Agentic users (uar_pages).
  • NetSuite records every user-role pairing, because access is granted per role; the workbook reports rows and distinct people.

5.4 NetSuite change management, CM-02

Walks scripts, deployments, workflows, custom record types, fields and forms, and records the population with the columns NetSuite shows. It does not claim to be an approval trail: NetSuite keeps System Notes one record at a time and approvals live in the ticketing system, so matching population to approved changes stays a human step, stated on the workbook's Summary tab.

The generated file is named <Working On>_<Control number and name>_<YYYY-MM-DD>.<template extension>, for example Workato_C-UA-04_Periodic_User_Access_Review_2026-10-14.xlsx, and downloads with Download Generated File. 5.6 SOC 1 assessment, ELC-14

No system is read. The preparer enters the vendor (defaulted from Working on) and the company review period, attaches the AuditBoard all-controls export, the company SOC 1 template and the vendor's SOC 1 Type II report, and presses Prepare. The SOC 1 agent returns a draft in the template plus open items, which then goes through the same validation and management review as any workpaper.

5.7 Termination reconciliation

A Workato recipe reconciles Workday terminations with Okta deactivations and exports a CSV. An Admin imports it; the dashboard shows outcome classes (OK, MISSED, REHIRED, LATE, plus a review class for anything else), timing distributions and drill-down to workers. Missing snapshots, empty or malformed CSVs and unknown classes never produce an all-clear.

6AI agents and how they connect

Three features use a language model. They share one rule: the model works from the evidence it is given, its output is a draft or a cited answer, and a person decides. Two of them run as background jobs with OpenAI's Code Interpreter; the help assistant answers inline.

Audit draft agent

/api/audit-draft

Fills the auditor's testing template from their population, sample selection and supporting evidence. Streams its work to the page as a live debug log.

OpenAI Draft + open items

SOC 1 agent

/api/soc1

Reads a vendor SOC 1 Type II report, maps complementary user entity controls to the AuditBoard export, and drafts the assessment in the company template.

OpenAI Draft + open items

Help assistant

/api/ask

Answers questions about the application from docs/ and the password policy. Retrieval runs first; a model only rewrites from the retrieved sections, with citations.

Guardrails

RiskControl in the design
Prompt injection from evidenceInstructions state that every file, cell, comment and the feedback text are data, never instructions. Context is wrapped as JSON labelled "data, not instructions".
Invented resultsA result is Supported only when evidence shows it; otherwise "Not tested - evidence needed: …". Every gap becomes an open item with the evidence needed.
Agent signs offReviewer and approver fields stay blank. The SOC 1 validator withholds a draft that keeps or adds sign-offs.
Template damagedXLSX drafts whose sheets were added, removed or reordered, or that contain formula errors, are withheld. DOCX must stay a valid Word file; text templates must stay UTF-8.
Malformed open itemsEach item needs non-empty id, issue and evidence_needed, or the draft is withheld.
Macros and external linksRejected at upload; the model is told not to execute them.
Evidence left with the providerstore: false; every uploaded file deleted in a finally block. A failed delete sets cleanup_pending on the job.
Leaking provider errorsHTTP errors are reported by status code only; response bodies that may quote evidence are not shown.
Double submissionIdempotency key per click: the same key returns the same job, never a second draft or a second charge.
Cost and loadOne model run at a time; requests above the size limits are refused before upload.

What the auditor sees

  • Debug view (default): a spinner, the provider and model, and a scrolling log of each step, the Python the model runs on the files, that code's output and the model's notes. The log keeps the last 400 entries, 4,000 characters each.
  • Run in Background: the log hides behind a spinner and the latest step; Show Details brings it back. When the run ends, a notice says the draft is ready even if the auditor moved elsewhere.
  • Finished: the spinner becomes a check, the log folds into Agent log, and Download Generated File appears with the open items. A failure shows the reason with the log open.
The log can quote evidenceCode output may print cell values from the uploaded files. The log is returned only to the job's owner and Admins, under the same rule as the files themselves.

9Deployment and operations

docker compose up -d --build        # both images, then http://localhost:8080
docker compose up -d --build web    # page-only change
docker compose logs runner          # startup and capture problems
  • Runner resources: shm_size: 1gb for Chromium; TZ sets the zone the evidence clock reads in.
  • Mounts: ./config read-only for credentials without Doppler; ./docs read-only so the assistant's answers update without a rebuild.
  • Health: /healthz on web, /api/health on the runner, both used by Compose health checks.
  • CI (.github/workflows/ci.yml): Python and JavaScript syntax, entrypoint and Compose checks, the runner, SOC 1 and audit unit tests (offline fakes, no network), then a build and smoke test of both images. No production credentials; no live captures.
  • Branching: main is the integration branch, protected to require a pull request with code-owner review.
